# Resume Quality Benchmark

This benchmark is for comparing current resume outputs against reference outputs and external ATS scoring tools. It is intentionally separate from application code.

## Folder Structure

- `profiles/` - Source candidate profiles used as benchmark inputs.
- `jds/` - Job descriptions used as benchmark inputs.
- `current_outputs/` - Resumes generated by the current system.
- `reference_outputs/` - Human-reviewed or target-quality resumes for comparison.
- `external_scores/` - Screenshots, exports, or notes from third-party ATS/review tools.

Each benchmark case should use the same case id across folders.

Example:

- `profiles/swe-backend-001.md`
- `jds/swe-backend-001.md`
- `current_outputs/swe-backend-001.pdf`
- `reference_outputs/swe-backend-001.pdf`
- `external_scores/swe-backend-001.md`

## Review Workflow

1. Add the source profile and JD.
2. Generate a current resume output and save it in `current_outputs/`.
3. Add a reference resume in `reference_outputs/`.
4. Run the current resume through one or more external ATS/review tools.
5. Record internal and external scores in `score_comparison.csv`.
6. Complete the review template in `../docs/resume-quality-gap-report.md`.

## Review Criteria

Use a 1-5 score for each criterion unless a specific test requires a different scale.

| Criterion | What To Check |
| --- | --- |
| Keyword match | Whether the resume includes important JD terms, required technologies, role-specific nouns, and seniority indicators without keyword stuffing. |
| Role alignment | Whether the resume presents the candidate as a strong fit for the target role, including domain, responsibilities, seniority, and business impact. |
| Bullet quality | Whether bullets are specific, outcome-oriented, quantified where possible, and written with clear action, scope, and result. |
| Skills coverage | Whether required and preferred skills from the JD are represented in skills, summary, and experience sections. |
| ATS parseability | Whether the resume uses ATS-friendly structure, consistent headings, readable dates, standard section labels, and avoids formatting that may break parsing. |
| Recruiter readability | Whether a recruiter can quickly understand fit, strongest evidence, progression, and differentiators in a short skim. |

## Scoring Guidance

| Score | Meaning |
| --- | --- |
| 5 | Excellent; ready to use with minor or no edits. |
| 4 | Strong; small gaps or polish issues remain. |
| 3 | Usable but uneven; meaningful edits recommended. |
| 2 | Weak; misses important role requirements or has quality issues. |
| 1 | Poor; likely to fail ATS or recruiter review. |

## Case Notes

For each benchmark case, capture:

- Case id
- Target role
- Candidate profile source
- JD source
- Generation date
- Internal ATS score
- External ATS score
- Quality reviewer
- Main gaps
- Recommended fixes
